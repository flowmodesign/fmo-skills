# Brand-driven conversational creation

Use the same actual graph/native tools in Flow, Designer and MCP. The MCP host remains the assistant; do not start another in-app AI loop. These routes describe outcomes and useful decisions, not mandatory tool sequences or graph topology. Choose real compatible nodes/functions from current capabilities, existing work, marketplace methods and the human's instructions.

## Intake and grounding

On a genuinely new creation offer an existing Brain brand, creation from scratch, or explicit skip. Reuse settled choices. Accept uploaded materials, assets, documents or free text. Offer brand research/segments, design-system refinement and logo upload/wizard/skip only where helpful and supported. Do not create a compulsory brand/research step for an already authorized bounded task. For a new brand, use discovered research/design-system/logo providers under actual paid authority as needed, save an actual Brand with write_record when the human asks, show/iterate it and connect_project_brand only after the human accepts that exact record. Do not replay a previous onboarding draft or promise repeat free creation. In write_record, put the narrative body in the top-level markdown argument. fields_json contains only declared typed Brand keys with string values, never body or markdown. Correct an actionable validation refusal using its actual valid-field receipt within the approved scope; verify the saved record without broadening the schema or claiming a failed write succeeded.

Read actual brand/assets/design-system and relevant records or RAG. Read creation preferences when available; saved evidence is subordinate to current human instructions. Ask one useful missing question about goal/platform/audience or present a broader plan according to the human's pace. Clarify material conflicts with protected identity/claims. Use explicit compatible model choices; if absent, ask or recommend from actual current capabilities before generation. Only explicit human statements may be remembered as pace/model preferences. Never infer provider suitability from a display name or silently substitute a pinned model.

Keep factual content separate from proposed creative direction. Brand voice does not authorize new product, event or offer facts: do not invent dates, prices, quantities, availability/capacity, deadlines, destinations, RSVP methods or performance claims. Use only the current brief and verified sources for these. For optional unknown details, omit them or label an editable placeholder; ask one focused question only when the missing fact blocks the result. Before saving copy, check every concrete claim against the brief and sources. A plan approval accepts its stated direction, not unstated factual additions. Human iteration corrects the existing saved owner, not a duplicate.

For simple copy artifacts, inspect the current graph and the relevant native capability once, then create each independently editable document with its complete known content and purpose name in the original create call when that schema supports it. Do not inspect sockets when no wiring is needed, split known initial content into needless create/read/update rounds, or reread unchanged capability/schema receipts. Read back the actual saved copy after a write and check the requested scope; reuse current original evidence without treating a successful write or draft as human approval. Batch independent tool calls only when the actual tool and current authority support it; dependent edits and verification remain ordered.

## Advisory routes

- **Image posts:** choose platforms and objective, align sourced references and a plan; optional trends/hooks/content harvesting or an existing brief. A typography/simple-shape design can use its first native editable layout as the visual draft; generated-image concepts use a capability-checked image mockup. Iterate with the human before requested derivatives. Build approved image concepts as editable layers and requested platform sizes after human approval. Native adCampaign can fit; discover its actual supported master, editable-build, size and variation tools first. Image generation and raster splitting are not prerequisites for live text/vector layouts.
- **Text posts:** choose platforms, brand voice/context and message plan; write platform-specific copy and iterate manually or with AI. No compulsory image mockup or media generation.
- **Carousel:** follow the image route with a cohesive narrative, hierarchy and continuity across separately editable cards. Reuse the original native Graphics document (Designer kind `image`), with direct child roots inside `.dsn-stage` carrying unique `data-dsn-card` ids, a shared requested pixel resolution/aspect and separate live text, image and shape layers. Reuse approved assets and the same source direction; a carousel is separate from a timed slide deck.
- **Web pages:** establish page type/goal and actual brand/assets. Offer optional inspiration/mockup/reference; build original editable layout, thoughtful effects/interactions, iterate and add requested pages. Preserve native owner/source identities. Staging/domain/publishing are available only through discovered supported tools; publication needs explicit human approval for the actual destination and the original publication/access/cost guards.
- **Ads:** first ask which platforms, placements and delivery formats the campaign needs; do not assume Google placements. Use a suitable native editable text/graphic draft or generated-image concept with verified campaign placements, copy constraints, sizes and requested angle variations. Preserve connected Brand fonts, weights, palette and assets, or its explicit skip; inspect current source and rendered pixels. Existing approved editable masters use the original HTML master/size/variation tools without unnecessary raster generation. Do not invent platform trafficking or performance proof.
- **Slide deck:** use a coherent carousel-like narrative for the stated audience, approved direction and editable slides. Optional simple animation must be supported and verified; do not claim motion/audio from a still.

- **Videos and reels:** choose the goal, audience/platform, source material, length, aspect and sound; use the current capabilities to propose a suitable path. For a website product reel, the original Reel Brief, Storyboard and Produce nodes support preparation, board review, filming, scene/voice edits and native composition delivery. New Reel briefs default to `board:review` before filming. If the person requests storyboard-first or approval before final video, show the actual still board and wait for their acceptance of its current direction before filming. `review:auto` controls later moving-draft checks and does not approve a board. Honor explicit `board:skip`, saved preferences and compatible alternative routes when the person chooses them. The original site capture/motion agent needs the desktop app. Use read_storyboard or read_motion_reel before edits, and the matching original tools for the actual stored storyboard type. A still board approves direction; a current moving playblast/preview must be watched before claiming motion quality. Inspect typography, safe areas, cuts, timing, real recorded interactions and requested sound; apply motion-preview craft where compatible. Iterate in the owning node/editor and export through the original Video Editor/Render tools when requested. Discover document ownership first: current Produce rebuilds its own composition from the storyboard, so do not promise that downstream manual editor changes survive Produce reruns or large motion revisions. Uploaded/generated footage and narrated videos use only actual compatible producers and supported editor functions; this starter does not establish an explainer/avatar engine. A named blueprint is optional guidance, never a required recipe.

- **Photoshoot:** establish the subject, uploaded photos/references, intended use and lighting; reuse the existing product-photoshoot skill or compatible product/portrait reference-pack methods where helpful. Preserve actual product geometry, identity, logo and palette. Generate one initial shot, show it in chat, review and iterate before the requested set. Select only actual supported models and lighting/editing capabilities; no invented studio node, mandatory large recipe or dedicated lighting-wizard claim. The native Designer media format stores shot assets in the project library. Move an approved shot to an editable page/ad only when requested.

Keep the original Work association across the brief, storyboard, editor and render: use a purpose name, current full-flow/source scope, last chat and saved artifact references through the existing tools. Manual model/skill choices remain authoritative; Auto uses original JEV policy only on supported adapters. The Reel script supports the ordinary reasoning models, while the current website motion tool loop supports Claude models: report an incompatible pin before spending, never silently substitute it. Board or automatic review settings grant no paid authority; use the original quote, wallet, provider, currentness, cancellation and root-budget guards. Explicitly authorized automatic production may use the original checks, but never treat a still board as a moving preview. Unsupported avatar/dedicated studio-wizard abilities remain separate; disclose unsupported scope.

## Human approval, delivery and memory

A reviewer PASS is not human mockup approval. Do not convert a proposed mockup into final editable layers/sizes before explicit human approval, unless the current human explicitly authorizes skipping that phase. Respect real paid consent, wallet/root/provider/currentness/Stop guards; a starter or method grants no spending or mutation authority. Ask/Plan stay read-only.

Preserve original source, assets, references and actual revisions through iteration and variants. Review current editable layers/copy, crops, sizes and real delivered pixels. Report missing scope honestly. After the human approves a saved creation, automatically retain its actual approved direction/reference evidence in the current linked brand using remember_brand_creation, unless the human opts out. The standing creation workflow authorizes retention; no additional save-approval question is needed. Quote the actual human creation approval: reviewer PASS, tool success and draft mockups are not human approval. Use only the exact current linked brand and real durable saved references; respect explicit brand skip or retention opt-out, never silently connect an unlinked brand, fabricate asset URLs or overwrite unrelated fields. Remember explicit user pace/model statements through the original shared preference tools, not a new storage path. Saved approvals and references remain available to future chat/brand context. Suggest one useful supported next task; do not automatically run it or mark an unverified output complete.
